# TAM Cap client distribution

The `v0.6.1-tam.2` desktop packages connect to `https://videos.trulyauthenticmarketing.com`. The unchanged Chrome extension remains at its `v0.6.1-tam.1` URL. `manifest.json` records each exact URL, byte count, SHA-256 hash, and native CI source revision. `checksums.txt` covers the exact download filenames. The R2 bucket `tam-cap-downloads` stays private; the application Worker serves only allowlisted `/downloads/` paths through its existing readiness boundary.

Desktop sign-in now opens the instance's HTTPS approval page. After the owner signs in and approves, the app exchanges its private verifier for a desktop credential through HTTPS; the browser finishes at `/desktop/complete`. No localhost callback or reusable credential appears in the browser URL. Requests expire after ten minutes and are consumed once. Old desktop clients show an update-required page when starting sign-in. Existing valid sessions are preserved by an installer update.

This desktop release also fixes duplicate signed Content-Type headers that prevented thumbnail upload and stopped Instant recordings from completing. Completed segment manifests can recover through the owner share page. Originals remain retained. A production Windows recording was recovered through the existing pipeline and made editable; the updated native packages compiled and passed their packaged-binary checks, while the repaired HTTPS handoff passed a separate production integration check.

The Windows x64 installer and Apple Silicon macOS DMG are self-built Cap GPUI 0.6.1 packages. Their CI jobs executed the packaged native binary with `--print-distribution` and verified `selfHosted=true`, the TAM server URL, instance identifier `com.trulyauthenticmarketing.cap`, and `automaticUpdates=false`. That probe verifies binary loading and configuration; it does not verify screen recording, microphone permissions, or desktop sign-in. Native recording acceptance remains a separate check on each operating system.

The macOS package is ad hoc signed and is not Apple notarized. macOS can block its first launch pending local approval or organization policy. The Windows installer is unsigned. Distribute these builds through the team's managed installation process and verify the SHA-256 hash before installation. Updates are manual or organization managed; the upstream Cap updater is disabled, and the fork uses separate application data.

For Chrome, unzip `TAMCap-Chrome.zip`, enable Developer mode at `chrome://extensions`, and choose **Load unpacked** with the extracted folder. Its stable extension ID is `ffocnmodhfclminiaapbfapkehcppkga`. The staging extension has a separate identity and is excluded from this release manifest. The ZIP includes the upstream license files. Production sign-in passed through native Chrome identity without a preview key or identity shim. The shipped package also completed a five-second synthetic current-tab capture, private R2 upload and production share playback at 1920×1080. This check used generated tab visuals/audio with microphone and camera disabled; it does not claim hardware capture or other recording modes were tested. Distribution remains manual unpacked installation, not Chrome Web Store publication.

Source and license are available from [the TAM Cap fork](https://github.com/keepinitgreen93/tam-cap/tree/codex/cloudflare-self-host). Each native artifact's exact source revision is recorded in the manifest. These are self-built fork packages, not official Cap commercial binaries or store publications.

To add a verified package, obtain it from the successful native CI artifact, confirm the packaged-binary probe passed, and compute its local SHA-256 and byte count. Upload the package to `tam-cap-downloads/<release>/<filename>` using `wrangler r2 object put --remote --file <local-package>`, then verify the protected Worker download's HEAD status and Content-Length. Update this manifest, checksums, and `apps/web/data/self-hosted-downloads.ts` together. Publish `manifest.json` at the bucket root and `TAMCap-checksums.txt` under the versioned release prefix. Do not change the readiness gate as part of artifact upload.
